# linux-hardening-project

## Descrizione

Questo progetto documenta un'attività pratica di **security auditing e system hardening** eseguita su una propria installazione di Kali Linux.

L'obiettivo è stato analizzare la configurazione di base del sistema, individuare impostazioni non ottimali ereditate dai **default di sistema** e correggerle applicando misure di hardening appropriate.

Ogni intervento è stato documentato seguendo un approccio **before/after**, riportando la configurazione iniziale, il comando utilizzato per effettuare la modifica e il relativo output dopo l'applicazione della correzione.

## Attività svolte

Il laboratorio comprende:

- audit iniziale della configurazione del sistema;
- individuazione di configurazioni non ottimali;
- analisi dei rischi associati alle configurazioni rilevate;
- applicazione delle misure di hardening;
- verifica delle modifiche effettuate;
- documentazione before/after di ogni intervento.

[Visualizza il laboratorio →](./project-files/)

## Metodologia

Per ogni configurazione analizzata è stato seguito questo approccio:

1. **Before** — verifica della configurazione iniziale;
2. **Analisi** — identificazione del problema e del relativo rischio;
3. **Hardening** — applicazione della correzione;
4. **After** — verifica della nuova configurazione;
5. **Documentazione** — raccolta del comando utilizzato e del relativo output.

## Strumenti utilizzati

- Kali Linux
- Linux Terminal
- Bash
- Standard Linux security and system administration utilities

## Obiettivi

Il laboratorio è stato realizzato per sviluppare competenze pratiche relative a:

- security auditing di sistemi Linux;
- identificazione di configurazioni non sicure o non ottimali;
- Linux system hardening;
- gestione e verifica delle configurazioni di sistema;
- analisi dei rischi derivanti dalle configurazioni di default;
- documentazione tecnica delle modifiche effettuate.

## Note

1. Le attività documentate in questa repository sono state eseguite esclusivamente sulla propria installazione di Kali Linux e in un ambiente controllato per finalità di formazione e laboratorio.

2. Ogni intervento è documentato attraverso la configurazione **before/after**, con i comandi utilizzati e i relativi output, permettendo di verificare direttamente le modifiche effettuate.
